Recovery actions

Restore (PITR)

Loads a backup snapshot into the isolated lab DB, then replays binlogs forward. Lab only — never touches prod. until HEAD replays everything; set a timestamp to stop earlier. Skip replay = snapshot as-is.

Diff (lab vs prod)

Compares lab vs prod table-by-table on primary-key id. Reports rows the lab has that prod is missing. Read-only. Run a Restore first so the lab is current.

Export (lab-only rows)

For one table, writes an INSERT IGNORE .sql of the rows prod is missing, saved to disk for you to review. Never auto-applied to prod.

Writes INSERT IGNORE .sql for human review. Never auto-applied to prod.

Torrent validate

Cross-checks one torrent: DB row ↔ its .torrent file ↔ recomputed info_hash. Confirms all three agree. Read-only. Enter a numeric id or 40-hex hash.

Reset lab (destructive)

Stops the lab and deletes its datadir for a clean slate. Lab only — prod is never touched. Type RESET to arm.

Stops the lab and deletes mysql_lab. Prod untouched.

Apply & disaster recovery (writes prod — password-gated)

Apply export → prod

Applies an export .sql to PROD as additive INSERT IGNORE — adds missing rows, overwrites nothing. Needs the prod DB password. Dry-run runs in a rolled-back transaction; a backup is taken before commit.

Additive INSERT IGNORE. Backup-first + dry-run run before commit.

Build apply kit (read-only)

Generates a combined .sql plus the exact terminal one-liner to apply it yourself. The dashboard never writes prod here — this is the manual fallback.

Combined .sql + exact terminal one-liner. Dash never writes prod. The fallback.

Maintenance

MySQL table upkeep on prod. check = read-only scan. analyze = refresh row-count estimates (cheap). optimize = rebuild table to reclaim space (locks it, backup-first). analyze/optimize need the prod password.

check reads. analyze refreshes the row estimates. optimize reclaims fragmentation (locks/rebuilds, backup-first).

Full DR: snapshot → PROD (destructive)

Disaster recovery. DROPs and recreates the PROD schema, imports a snapshot, replays binlogs to until — wipes current prod data. Backup-first. Set until from the damage timeline to stop before the bad event. Type RESTORE PROD to arm.

DROP+recreate prod schema → import → replay to until. Backup-first. Set until from the timeline to stop before the wipe.

Damage timeline

Destructive events in the replay window. Click one → sets Restore until to just before it, so you recover up to — not through — the damage.
